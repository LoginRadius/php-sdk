LoginRadius PHP SDK

Every endpoint below comes from the shared demo contract in the shared SDK manifest — the same nine routes every LoginRadius SDK demo exposes. Only this page's design is PHP's own.

Register

Mints a SOTT server-side; the browser never sees the secret.

—

Session

Log in, then log out to clear the demo session cookie.

—

Second factor required

The login returned a challenge. Its token is held in a separate short-lived cookie — a session cookie will not open these routes. 

—

Passwordless login

No password: a one-time code is emailed or texted to an existing user, then verified here to start a session. A tenant with MFA enabled still enforces its second factor afterward, same as the Session card. 

—

Forgot password

The reset token arrives by email and lands back on this page; the SMS route sends an OTP instead.

—

Reset password

Paste the token from the reset email, or let the emailed link fill it in.

Delete account

The demo refuses any address other than the one you are signed in as. The underlying API is admin-scoped and would delete any account in the tenant.

Custom Objects

—

Access token

Refresh uses the /manage/ operation. The native variant takes the access token as a query parameter, which would put a bearer credential into access and proxy logs. Refreshing rotates the session's tokens server-side, so the cookie does not change. 

—

Multi-factor authentication

Optional. Where Duo returns the user after its challenge — only needed if this tenant has Duo configured. Left blank, the parameter is omitted entirely rather than sent empty. 

—

Passkey

WebAuthn needs a secure context. http://localhost counts, so this works as shipped; over plain HTTP on any other host the browser refuses.
